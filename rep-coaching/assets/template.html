How a score is made

From one call to a coaching priority.

Four steps turn a conversation into a number a manager can act on.

Step 1 · Every call gets a 0–5 on every skill

0Not observedNo evidence in this conversation; not a judgment of the rep's overall ability.
1TraceA passing mention, nothing specific.
2PartialDiscussed, but stayed generic. No name, no number.
3SubstantiveAt least one hard detail, confirmed by the buyer.
4StrongSeveral confirmed specifics: names, figures, dates.
5NailedFully qualified by the method's own definition.

Step 2 · Combine call and email

The call score and the email score for the same deal merge into one score out of 10. When both sources show the skill, the combined score climbs higher than either alone.

combined = (1 − (1 − call ÷ 5) × (1 − email ÷ 5)) × 10

A rep's score on a skill is the average of that combined number across all their deals.

Step 3 · Weigh each skill

The engine weight is a relative share of positive score differences between historical won and lost deals. It is an exploratory association, not a causal effect or a win-probability estimate. The explains the calculation.

Step 4 · Rank the gaps, per rep

Three things decide a skill's place on a rep's list: its engine weight, how far the rep is from a perfect 10, and the rep's rank on the team. Squaring the rank makes being near the bottom of the team count most.

priority = weight × (10 − score) × (team rank ÷ 11)²

Engine Weights

Which skill scores were associated with wins?

Weights summarize unadjusted differences in historical scores between won and lost deals. They are exploratory associations—not causes or predictions—and can reflect other factors such as segment, deal size, lead source, or opportunity. Review sample sizes and context before using them.

The idea in one minute

Not every skill is worth the same.

1

What it is

An engine weight is the normalized share of positive average-score differences between won and lost deals, within one framework. It is descriptive, not a causal or predictive model.

2

How it was learned

Each skill's weight comes from how much higher it scored on deals that were won than on deals that were lost. A skill that barely differs gets little weight; one that scored higher on lost deals gets none.

3

How to read it

Compare weights only within the same framework. They do not represent percentage points of win probability; small samples and confounding can make the association unstable.

The table at the heart of it

One master table. Two kinds of row.

Everything else is built from this table, so its rules matter most. Below is what three {{COMPANY}} rows look like, with most of the 13 skills hidden to keep it readable.

The key

Each row is identified by deal ID + call date. A deal has exactly one CRM row (call date left blank) and one extra row for every call. The same key twice means a duplicate, and the write is refused.

Three columns per skill

Every skill has a score (a whole number, 0–5), a reason (what happened on the call) and a coaching note (what to do next time). The coaching cards on the Rep Coaching tab quote these two text columns.

Attach each call to its deal

Put the deal ID in every transcript's file name, for example call-transcript--pricing-review--BW-7Q2K4M.txt. A call with no deal yet gets a "potential" row, which is joined to the real deal once one exists.

The scoring prompt

One written prompt does the reading.

The AI model gets the same instructions for every call. Most of the quality of the whole system comes from how carefully this prompt is written.

1

Role and input

Who the model is, what a {{COMPANY}} sales call is, and the transcript itself.

2

Theme rule

Reuse labels from an approved list, word for word, so charts count identical words instead of near-duplicates.

3

Evidence rule

Every score needs a short quote or paraphrase from the transcript. A reason that could be written without reading the call is a failed answer.

4

One scoring scale

The same 0–5 scale for every skill, with a plain definition of each step. Scores stay comparable across skills and across calls.

5

A block per skill

For each of the 13: the question, what to listen for, and an example of a 1, a 3 and a 5.

6

Output format

Exact field names, whole numbers only, and what to write when the evidence is missing.

Lessons learned the hard way
Eight rules worth knowing before you start.

    

      
01
Count deals, not rows
One deal has many rows, one per call. Merge by deal ID before any total, or the pipeline can look twice its real size.

      
02
Never rebuild the table from scratch
Change only the deals that changed, and copy the table to a backup folder before every write. A full rebuild can quietly drop columns other stages depend on.

      
03
Whole numbers, always
A score saved as the text "2.0" can break the reader downstream and make a rep's scores disappear without any error. Read loosely, write strictly.

      
04
Watch for double recordings
The same call can be captured twice under two titles. Compare date, length and wording, and record the copy as a duplicate rather than loosening the key check.

      
05
Fast model for volume, strong model for judgement
Use a fast, low-cost AI model for the per-call and per-thread scoring. Save a stronger model for one-off summaries a manager will read.

      
06
Keep the computer awake
A laptop that sleeps halfway through a run looks exactly like a slow AI service. Check for sleep before blaming anything else.

      
07
One source of truth for each fact
One roster file for reps, one schema file for columns, one template for the dashboard. Edit the source, never a copy.

      
08
Automate only what passes
A watcher waits until new files stop arriving, runs the stages in order, and marks a run done only when every check passes.

    

  


  

    
The build plan
Six weeks from nothing to a working system.
Each week ends with something you can open and check. Don't start the next week until this one's check passes.

    

      
Week 1
Collect and build the table
Export deals from the CRM, transcripts from the call recorder, and email threads per deal. Build the master table with its key and backups.
Done when: every call sits on the right deal.

      
Week 2
Write and test the prompt
Draft the scoring prompt. Score 20 calls by hand, run the model on the same 20, and fix the prompt until the two agree.
Done when: model and human are within one point on most skills.

      
Week 3
Score everything
Run the prompt over every call and every email thread. Combine them into 0–10 per skill per deal.
Done when: every deal with a call has 13 combined scores.

      
Week 4
Learn the weights
Compare won and lost deals to set each skill's engine weight. Build the rep × skill grid and the priority ranking.
Done when: the weights make sense to a sales leader.

      
Week 5
Build the dashboard
One HTML template edited by hand, with the data poured in by a script. Add the coaching text from each rep's own calls.
Done when: every tab draws and the screenshots look right.

      
Week 6
Automate and guard
Add the table checks and page checks, then a watcher that runs the whole chain when new files land.
Done when: a refresh runs with nobody touching it.
